# Skyrim Special Edition and Anniversary Edition BSA

Issue #44 activates versioned-BSA wire version `0x69` through the existing
public archive model. The public family is `SSE_BSA`; the CLI selector is
`-sse`. Stored payloads remain the family default, while bare `-z` and
`-z:lz4f` select the family LZ4-frame codec.

The common reader and writer now select a 24-byte folder record for `0x69` and
retain both padding words in `EntryMetadata.VersionedBsa`. Canonical output
writes zero padding. Nonzero input padding remains bounded and decodable but is
classified as Tolerated Noncanonical. Common name handling, unsigned hashing,
collision-safe ordering, compression toggles, explicit embedded names,
splitting, sharing, and publication behavior remain shared with `0x68`.

Compressed entries use a lazy, parent-owned incremental LZ4-frame decoder. The
family encoder emits level 12, independent blocks, a 4 MiB maximum block size,
auto-flush, and no content size, dictionary identifier, or checksums. The
family profile is recorded separately as `jbsa-bsa-069-lz4-v1`, layered on the
previously qualified `jbsa-lz4-v1` Windows x64 runtime so issue #43's historical
profile identity remains unchanged.

## Requirement trace

The governing registry is specification **0.16.0**. Issue #44 directly owns:

- `JBSA-BSA-001`: stored/LZ4-frame/mixed decode and encode with foreign-codec
  rejection before source or destination effects.
- `JBSA-BSA-004`: 24-byte folder records and canonical zero padding.
- `JBSA-BSA-010`: the exact family LZ4-frame profile and complete stream/size
  consumption.
- `JBSA-BSA-013`: automatic family flag masking.
- `JBSA-BSA-014`: checked validation and SSE embedded-name warnings.
- `JBSA-BSA-015`: inherited split, sharing, and deterministic ordering rules.

The implementation also exercises the inherited common BSA, codec, library,
CLI, conformance, and performance requirements named in the ticket.

## Evidence

The project-authored `tests/fixtures/bsa069` corpus contains independently
generated Skyrim SE and AE stored, LZ4-frame, mixed, and embedded-name vectors.
`build/validate-bsa-wire.py` independently parses the 24-byte layout and
decodes LZ4 blocks without using JBSA or an LZ4 provider.

Focused library, CLI, corpus reproduction, independent validation, and both
directions of the digest-pinned local BSArch differential pass. The oracle's
small encoded frames advertise a 64 KiB maximum block size; decode accepts that
ordinary independent frame, while canonical JBSA encode separately asserts the
specified 4 MiB maximum.

The development performance checkpoint is recorded under
`evidence/issue44-performance`. It covers matched 16 MiB stored and LZ4-frame
pack, extract, output-size, bounded heap-pool peak, and 64 repeated 4 KiB prefix
reads. This checkpoint is regression evidence, not formal Performance v1.

The active conformance catalog's `bsa-069` goldens still require the separate
review and explicit approval process required by `JBSA-CONF-007`. No compressed
Binary Conformance claim is made.
